# Figma `최종` 포트폴리오 시각 정리 설계

## 목표

Figma 파일 `3vc2UxVVqBrS7FyOcGdjn4`의 `최종` 섹션만 다듬는다. 현재 16개 A4 페이지의 문구, 프로젝트 순서, 이미지, 성과 수치와 근거는 유지하면서 여백·그리드·색상·타이포그래피·반복 요소를 하나의 시각 체계로 통일한다.

## 범위

- 대상: 링크의 `19:288` 노드가 속한 `최종` 섹션 내부 A4 프레임
- 유지: 모든 텍스트 내용, 페이지 순서, 프로젝트별 이미지, 결과 수치, 근거 문구
- 변경: 프레임 정렬, 내부 여백, 열 비율, 카드 간격, 이미지 크기, 선과 배경색, 글꼴 크기·두께·행간·자간·명도
- 제외: `최종` 밖의 원본 템플릿·중간 시안, 내용 요약·추가·삭제, 페이지 수 변경

## 시각 방향

흑백 에디토리얼 스타일을 기본으로 하고 개선 결과에만 저채도 딥 그린을 사용한다.

- Paper: `#FBFAF7`
- Ink: `#1F1F1D`
- Body: `#55534E`
- Muted: `#7B7871`
- Line: `#D8D5CE`
- Surface: `#F2F0EB`
- Result Accent: `#315D4E`

그림자는 사용하지 않고 1px 선, 평면 카드, 넉넉한 여백으로 계층을 만든다. 프로젝트별 장식색은 제거하되 프로젝트 스크린샷 안의 의미 있는 색은 유지한다.

## 공통 레이아웃

- A4 프레임 크기는 현재 값을 유지한다.
- 모든 페이지에 동일한 안전 여백과 8px 기반 간격 체계를 적용한다.
- 상단 헤더는 `페이지 번호 — 구분선 — 섹션명` 구조와 위치를 통일한다.
- 본문은 한 열 또는 두 열 중 내용량에 맞는 구조를 사용하되, 같은 유형의 페이지는 같은 열 비율을 사용한다.
- 카드·수치 박스·이미지·캡션의 좌우 기준선을 맞춘다.
- 내용이 적은 페이지는 아래로 흩어놓지 않고 상단부터 밀도 있게 배치한다.

## 페이지 유형

### 표지

이름, 개발자 정의, 한 줄 소개, 기술 영역, 연락처 순서를 유지한다. 모든 요소의 왼쪽 기준선을 맞추고 시각 자료는 사용하지 않는다.

### 프로필

자기소개와 기술 영역을 상단에 두고 프로젝트 이력·주요 활동·수상 및 선정은 하단 그리드로 정리한다. 타임라인의 선, 날짜, 제목, 설명 간격을 통일한다.

### 프로젝트 개요

`프로젝트명 → 서비스 한 줄 설명 → 서비스 개요/기술 스택 → 기간·역할 → 대표 화면 → 담당 기능·주요 성과` 순서를 유지한다. 프로젝트 이미지의 높이와 캡션 위치를 같은 규칙으로 맞춘다.

### 문제 해결

`페이지 제목 → 기술 태그 → 문제 → 원인 → 해결 → 결과 → 측정 범위·근거`의 읽기 순서를 통일한다. `문제`, `원인`, `1차 해결`, `최종 해결`, `결과` 라벨은 같은 스타일로 표시하고, 결과 수치에만 딥 그린을 적용한다.

### 묶음 프로젝트

프로젝트별 카드 구조를 통일하고 프로젝트명, 기간, 서비스 설명, 기술, 담당 기능의 위계를 같은 순서로 유지한다.

## 타이포그래피

파일에서 실제 사용할 수 있는 기존 한글 산세리프를 확인한 뒤 하나의 글꼴 계열로 통일한다. Pretendard가 이미 사용 가능하면 우선 적용하고, 그렇지 않으면 현재 파일의 주 한글 글꼴을 유지한다.

- 표지 이름: 52–60px, ExtraBold
- 페이지 제목·프로젝트명: 30–34px, Bold 또는 ExtraBold
- 소제목: 14–16px, Bold
- 본문: 11.5–12.5px, Regular, 155–165% 행간
- 캡션·근거: 9–10px, Regular
- 영문 섹션명: 9–10px, Bold, 넓은 자간

본문은 Ink보다 한 단계 밝은 Body 색을 사용하고, 보조 설명과 캡션은 Muted로 내려 제목과 명확히 구분한다.

## 수정 절차

1. `최종` 섹션과 내부 A4 프레임의 ID, 크기, 위치, 글꼴, 색상, 반복 구조를 읽는다.
2. 대표 페이지 세 종류(표지·프로젝트 개요·문제 해결)를 먼저 정리해 규칙을 검증한다.
3. 검증된 여백·헤더·카드·타이포 규칙을 나머지 페이지 유형에 적용한다.
4. 각 수정 단계에서 프레임 스크린샷을 확인하고 잘린 글자, 겹침, 이미지 왜곡, 기준선 불일치를 수정한다.
5. 마지막으로 `최종` 섹션 전체 프레임의 크기·간격·순서와 텍스트 내용 보존 여부를 검사한다.

## 완료 기준

- `최종` 밖의 노드는 변경되지 않는다.
- 16개 페이지의 내용과 순서가 유지된다.
- 페이지 유형별 헤더·여백·제목·본문·카드·캡션 규칙이 일관된다.
- 본문과 캡션이 인쇄 가능한 크기와 대비를 가진다.
- 텍스트 잘림, 요소 겹침, 프레임 밖 오버플로, 이미지 비율 왜곡이 없다.
- 결과와 개선 수치가 포인트 컬러로 빠르게 식별된다.
